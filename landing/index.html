Get grilled on your repo before your examiner does.

Grill reads a student's own codebase, asks timed questions that cite real files and lines, then sets a live change request graded by hidden tests in a sandbox. Not by model opinion.

The only reliable check today is a manual viva with a live change request. It's slow, it varies between examiners, and nobody can run one for every student. Grill runs it for the whole cohort and leaves the final call with the examiner.

How it works

Three steps, one pinned commit

  1. 01

    Submit a repo

    Sign in with GitHub, join a cohort with an invite code, and submit a repo and branch. Grill pins it to a commit hash so it can't change mid-viva, then analyses it with live progress.

  2. 02

    Answer the viva

    6 to 10 timed questions, each citing a file and line from your code. Follow-ups build on what you just said, and pasting is disabled.

  3. 03

    Ship a change request

    A small feature on your own code, written in the browser editor. Run the visible tests as often as you like; hidden tests in a sandbox decide the grade.

Features

The model proposes. The tests decide.

Grounded questions

Every question and judgement must reference a file and line that exists at the pinned commit. Code checks this before anything is shown.

Test-graded change requests

Hidden tests must fail on the original code and pass on a reference solution before a task is ever shown, so no task is impossible or already done.

Locked-down sandbox

A fresh container per run: no network, non-root, read-only image, CPU and memory limits, 30 seconds, then destroyed.

Consistent scoring

Rubrics stored as data, low-temperature structured output, multiple passes averaged. Re-scoring a session stays within ±5%.

Evidence on every score

Each judgement links to its question, the answer and the code it is about. Students see why they got the score they got.

Works when the API doesn't

Analysis is cached per commit and a recorded-session fallback keeps demos and exams running through a model outage.

For examiners

You stay in charge of the grade

AI scores are advisory until you confirm them. Run a whole cohort, then spend your time on the sessions that need you.

  • Create cohorts with an invite code, deadline and question count
  • Pick or edit the rubric and its weights
  • Watch session status across the cohort
  • Override any score with a written reason, logged in the audit trail
  • Export cohort results as CSV

Plugin

A “Verified” badge for your README

The Grill badge is a small vanilla JavaScript plugin. Drop one script tag into a portfolio and add a data-grill-badge element. It renders inside a Shadow DOM, so your site's CSS can't break it and it can't break yours. 

<script src="grill-badge.js"></script>
<div data-grill-badge
     data-user="student01"
     data-repo="shop-api"
     data-score="82"
     data-commit="a1b2c3d"></div>

Try it: the badge updates as you type, through the plugin's GrillBadge.update() API.

FAQ

Questions

Does Grill detect AI-written code?

No. Grill measures understanding, not authorship. It's fine if a tool helped write the code, as long as the student can explain and change it.

Can't students just ask another AI during the viva?

Time limits, disabled paste, follow-ups that depend on earlier answers and a change request on their own code make it much harder. It raises the bar; it doesn't claim to make cheating impossible.

Which languages are supported?

JavaScript and Node.js for the first release. Python and Java are planned later.

What if my repo has no tests?

That's fine. Grill brings its own test harness built on node:test and calls your exported functions or HTTP routes directly.

Can I delete my data?

Yes. Students can delete their sessions and profile at any time.
